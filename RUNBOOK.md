# Инструкция по запуску и использованию

Документ для раздела 8 ТЗ. Сервис работает **полностью локально**: после
загрузки весов интернет не нужен.

## 1. Требования

| | |
|---|---|
| Python | 3.9+ (проверено на 3.9.13 и 3.11) |
| GPU | NVIDIA с CUDA, 6 ГБ и выше. Без GPU работает, но примерно в 10 раз медленнее |
| Диск | ~3 ГБ: веса Faster R-CNN (167 МБ) + SigLIP (~800 МБ) + torch |
| ОС | Windows / Linux |

## 2. Установка

```bash
cd fortebank
python -m venv .venv && . .venv/Scripts/activate     # Linux: . .venv/bin/activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
pip install -r requirements.txt
```

> Отдельная виртуальная среда обязательна: проект требует `numpy>=2`, который
> конфликтует со старыми `scipy`/`statsmodels`, если они стоят глобально.

### Прогрев весов (один раз, нужен интернет)

```bash
python -c "from app.vision import _load_model; _load_model()"
python -c "from app.clipscore import _load; _load()"
```

После этого интернет больше не нужен. Веса лежат в `~/.cache/torch` и
`~/.cache/huggingface`.

## 3. Запуск

```bash
API_KEY=<ваш-ключ> uvicorn app.main:app --host 0.0.0.0 --port 8000
```

| Адрес | Назначение |
|---|---|
| `http://localhost:8000` | веб-интерфейс |
| `http://localhost:8000/docs` | интерактивная документация API |
| `http://localhost:8000/health` | проверка живости, **без ключа** |

### Публичный URL для жюри

```bash
cloudflared tunnel --url http://localhost:8000
```

Выдаёт публичный HTTPS-адрес; модели при этом остаются на вашей машине,
требование локальности не нарушается.

### Проверка автономности

```bash
docker run --rm --network none -v "$PWD:/app" -w /app python:3.11 \
  python -c "import os; os.environ['HF_HUB_OFFLINE']='1'; print('offline ok')"
```

В рабочем контуре задайте `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1` —
иначе `transformers` при старте попытается сходить в сеть за конфигом.

## 4. Использование интерфейса

1. Открыть `http://<адрес>:8000`.
2. Ввести API-ключ (сохраняется в браузере).
3. Перетащить `.mov` в зону загрузки или выбрать файл.
4. Нажать «Анализировать» — отображается статус и счётчик секунд.
5. Результат:
   - зелёная плашка «Нарушение не обнаружено», либо
   - красная «Обнаружены признаки возможных нарушений» и карточки событий.
6. Каждая карточка содержит: тип, таймкод, описание, 1–3 кадра-доказательства,
   цитату нормы, ссылку на источник и пометку статуса сверки.
7. Блок **«Проверьте вручную»** — увеличенные вырезы трёх зон на момент
   события: поверхность стола, зона хранения (шкаф и замок), рабочее место.
   Клик по вырезу открывает его во весь экран. Этот блок и есть основная
   польза сервиса: признаки нарушений мельче разрешения видео, поэтому
   решение остаётся за человеком (см. `LIMITATIONS.md`).

## 5. API

```bash
# шаг 1 — загрузка, ответ приходит сразу
curl -X POST http://<адрес>/api/v1/analyze \
  -H "X-API-Key: <ключ>" -F "file=@video.mov"
# {"job_id":"3f2a9c1e"}

# шаг 2 — опрос результата
curl http://<адрес>/api/v1/jobs/3f2a9c1e -H "X-API-Key: <ключ>"
```

| Код | Причина |
|---|---|
| `401` | ключ отсутствует или неверен |
| `415` | формат не `.mov` / `.mp4` / `.m4v` |
| `413` | файл больше `MAX_UPLOAD_MB` (по умолчанию 200 МБ) |
| `404` | `job_id` не найден |

Поля ответа — по схеме ТЗ. Дополнительно: `rule` (норма с цитатой),
`confidence`, `inspection_frames` (увеличенные зоны для ручной проверки),
`processing_sec`, `truncated`.

Размер ответа: около 0.5 МБ на одно событие, до ~2 МБ на четыре.

## 6. Настройка

Всё через переменные окружения, перезапуск не требует правки кода.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_KEY` | `dev-key` | **обязательно сменить в проде** |
| `CLIP_THRESHOLD_MULT` | `1.0` | рабочая точка: `0.2` — ноль пропусков и 82 % попаданий по таймкоду; `1.0` — лучшая accuracy 0.700 |
| `MAX_PROCESSING_SEC` | `240` | бюджет обработки; watchdog добивает через +10 с |
| `WORKERS` | `1` | параллельных анализов (на одной GPU больше обычно вредно) |
| `MAX_VIOLATIONS` | `8` | максимум событий на видео |
| `ANALYZER` | `real` | `none` / `demo` — заглушки для отладки |
| `EVIDENCE_FRAMES` | `3` | кадров-доказательств на событие (ТЗ: 1–3) |

## 7. Проверка качества

```bash
python evalkit/labels.py                      # разметка: 40 видео, 22 события
python evalkit/extract_states.py              # детекция в кэш (~2 мин, один раз)
python evalkit/run_eval.py --baseline offline # метрики по кэшу, секунды
python evalkit/run_eval.py --api http://localhost:8000 --key <ключ>
```

Режим `--api` повторяет ровно сценарий жюри: `POST` → поллинг `GET`.

## 8. Производительность

Замерено на RTX 4070 SUPER, ролики 10–145 с:

| Этап | Время |
|---|---|
| Детекция (Faster R-CNN, 3 fps) | ~2 с на ролик |
| Семантический скоринг (SigLIP, 2 fps) | ~0.7 с на ролик |
| Кадры-доказательства | <0.1 с |
| **Итого на видео** | **~3 с** при лимите 300 с |

Первый запрос после старта дольше на 5–8 с — загрузка весов в память.

## 9. Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| `401` на все запросы | `API_KEY` не совпадает с заголовком `X-API-Key` |
| Старт падает на `transformers` | конфликт numpy: поставить в отдельный venv, `numpy>=2` |
| Очень медленно | нет CUDA; проверить `python -c "import torch;print(torch.cuda.is_available())"` |
| `truncated: true` в ответе | сработал watchdog, отдан частичный результат; увеличить `MAX_PROCESSING_SEC` |
| Повторный анализ того же файла мгновенный | это кэш детекций по md5 в `var/cache`, так и задумано |

## 10. Что важно знать про результат

Сервис — **подсказка для проверки человеком**, а не заключение. Границы
применимости и известные ошибки описаны в `LIMITATIONS.md`; читать до
интерпретации результатов.
